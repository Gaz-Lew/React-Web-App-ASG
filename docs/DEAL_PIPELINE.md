# Deal Pipeline Dashboard

A clean, structured replacement for spreadsheet-based deal tracking in your CRM.

## ✨ Latest Updates

### New Status System

The old complex status system has been **simplified to 6 clear stages**:

```
lead → qualified → conditional → unconditional → settled / lost
```

### System Flags

Two automatic visual flags (do NOT override status):

- **🔴 Overdue**: `expectedSettlementDate < today` AND `status != "settled"`
- **🟡 Stuck**: `lastUpdate > 7 days ago` AND `status != "settled"`

### Create Deal Modal

New button in header to quickly add deals with proper defaults.

## Firestore Structure

### Collection: `deals`

```typescript
{
  id: string;                          // Auto-generated by Firestore
  clientName: string;                  // "John & Sarah Smith"
  status: DealStatus;                  // See DealStatus type below
  dealValue: number;                   // 850000 (in dollars)
  commissionTotal: number;             // 8500
  commissionPaid: number;              // 0 (starts at 0 on creation)
  expectedSettlementDate: string;      // "YYYY-MM-DD" format
  assignedTo: number;                  // Rep ID (FK → reps.id)
  lastUpdate: number;                  // ms epoch timestamp
  notes: DealNote[];                   // Array of note objects
  createdAt: number;                   // ms epoch timestamp
  createdBy: string;                   // Rep name
}

interface DealNote {
  id: string;                          // "note_timestamp_random"
  text: string;                        // Note content
  createdAt: number;                   // ms epoch timestamp
  createdBy: string;                   // Rep name
  createdById: number;                 // Rep ID
}

type DealStatus =
  | 'lead'             // Gray - New deal, just created
  | 'qualified'        // Blue - Client qualified, interested
  | 'conditional'      // Amber - Conditional approval received
  | 'unconditional'    // Purple - Unconditional approval
  | 'settled'          // Emerald - Deal settled, complete
  | 'lost';            // Red - Deal lost/fell through
```

## System Flags Logic

### Overdue Flag

```typescript
isOverdue = expectedSettlementDate < today && status !== "settled";
```

- **Visual**: Red row highlight + red badge showing days overdue
- **Does NOT change status automatically**
- **Clears when**: Status changes to "settled"

### Stuck Flag

```typescript
isStuck = daysSince(lastUpdate) > 7 && status !== "settled";
```

- **Visual**: Amber row highlight + amber badge showing days stuck
- **Does NOT change status automatically**
- **Clears when**: Status changes to "settled" or deal is updated

## Design Principles

### ✅ What We Follow

- **Simple and predictable logic** - No surprises
- **No automatic status changes** - You control the pipeline
- **Manual status updates only** - Via dropdown in drawer
- **Flags are visual only** - Never override your status
- **Clean separation of concerns** - Status ≠ Flags

### 🚫 What We Avoid

- ❌ No automatic status progression
- ❌ No DNQ (Did Not Qualify) logic
- ❌ No inline spreadsheet editing
- ❌ No complex nested collections
- ❌ No heavy date picker libraries
- ❌ No multiple Firestore queries per page

## Performance

- **Initial load**: Single Firestore `onSnapshot` subscription
- **Filtering**: Client-side with `useMemo` for efficiency
- **Sorting**: Client-side, toggle asc/desc
- **Search**: Real-time text matching on client name
- **Real-time**: Auto-updates via Firestore listener
- **Flags**: Computed on-the-fly, no extra storage

## Migration from Old System

If you have existing deals with the old status system:

```javascript
// Old statuses → New mapping
const STATUS_MAP = {
  Booked: "lead",
  "Appointment Set": "qualified",
  "Appointment Done": "qualified",
  "Application In": "conditional",
  "Under Assessment": "conditional",
  Approved: "unconditional",
  Settlement: "unconditional",
  Complete: "settled",
  // Any DNQ or lost deals:
  DNQ: "lost",
  Failed: "lost",
};

// Run this once to migrate:
import { getFirestore, collection, getDocs, updateDoc, doc } from "firebase/firestore";
const db = getFirestore();

async function migrateDealStatuses() {
  const snapshot = await getDocs(collection(db, "deals"));
  for (const dealDoc of snapshot.docs) {
    const data = dealDoc.data();
    const newStatus = STATUS_MAP[data.status];
    if (newStatus && newStatus !== data.status) {
      await updateDoc(doc(db, "deals", dealDoc.id), {
        status: newStatus,
      });
      console.log(`Migrated: ${data.clientName} → ${newStatus}`);
    }
  }
  console.log("Migration complete!");
}

migrateDealStatuses();
```

## Troubleshooting

### No deals showing?

- Create your first deal using the "Create Deal" button
- Check Firestore rules allow read access to `deals` collection
- Verify you're on the correct page (Sales → Deal Pipeline)

### Flags not showing?

- Ensure `expectedSettlementDate` is in `YYYY-MM-DD` format
- Check that `lastUpdate` is a valid timestamp (ms epoch)
- Flags only appear on non-settled deals

### Status not updating?

- Check Firestore write permissions
- Verify status is one of the 6 allowed values
- Check browser console for errors

### Create Deal failing?

- All required fields must be filled
- Deal value must be > 0
- Must assign a rep
- Check Firebase console for write errors
